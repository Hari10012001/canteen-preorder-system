# KIOT College Canteen Pre-Order System

A working final-year project prototype that lets a student pre-order canteen food,
choose a pickup slot, pay through a demo payment method, and collect the order by
showing a scannable QR code at the counter.

```
HTML / CSS / Vanilla JS  ->  REST API  ->  Spring Boot  ->  MySQL
```

---

## QUICK START

**Requirements:** a JDK (21 or newer), Maven 3.9+, and a running MySQL 8 server on
port 3306. Nothing else — no Node, no npm, no build step for the frontend.

1. Tell the app your MySQL password once, through a Windows environment variable.
   It is deliberately **not** stored anywhere inside the project:

   ```bat
   setx DB_PASSWORD "your MySQL password"
   ```

   Then open a **new** command prompt so the new variable is picked up. The
   database itself does not need to exist.
2. **Double-click `START.bat`.** It checks Java, MySQL and port 8080, builds the jar
   if the sources changed, starts the server and opens your browser.
3. Sign in with one of the demo accounts (the login screen also has one-click
   **Use** buttons):

   | Email | Password | Name | Student ID |
   |-------|----------|------|------------|
   | `student@kiot.edu` | `canteen123` | Hariharan P | 22CS014 |
   | `demo@kiot.edu` | `demo1234` | Demo Student | 22CS001 |

4. Browse the **Menu** -> add items to the **Cart** -> choose a pickup date and slot
   -> pick a payment method -> place the order -> show the QR code.

To shut down, double-click **`STOP.bat`**. Other helpers: **`STATUS.bat`** (is
everything healthy?), **`OPEN_APP.bat`** (open the app in a browser) and
**`DATABASE.bat`** (browse the data in MySQL).

The app is then at <http://localhost:8080>.

## 1. Tech stack

| Layer | Technology |
|-------|------------|
| Frontend | HTML5, CSS3, vanilla JavaScript (no React / Angular / Node / build tooling) |
| Backend | Java 21, Spring Boot 3.5.11, Spring Web, Spring Data JPA, Hibernate |
| Database | MySQL 8.0 |
| QR | ZXing 3.5.2 (server-side PNG generation) |
| Security | BCrypt via `spring-security-crypto`, plus an opaque in-memory session token |
| Tooling | Maven 3.9+, five Windows `.bat` helpers for start / stop / status / open / browse |

The frontend is plain files served as static content by Spring Boot, so there is
no bundler, no `node_modules`, and nothing to compile or install.

## 3. MySQL setup

The application creates and maintains its own schema, so in the normal case you do
not run any SQL yourself. Just make sure MySQL is running and the credentials in
`backend/src/main/resources/application.properties` match your own MySQL account.

**Recommended - let the app do it**

The JDBC URL contains `createDatabaseIfNotExist=true`, so the `kiot_canteen`
database and all five tables are created by Hibernate on startup, and the seeder
inserts the 2 demo users and the 17 menu items only if they are missing. Restarting
never duplicates rows.

### Credentials

`backend/src/main/resources/application.properties` holds **no password**. It reads
both credentials from environment variables and falls back to a default:

```properties
spring.datasource.username=${DB_USERNAME:root}
spring.datasource.password=${DB_PASSWORD:}
```

Set them once for your Windows user, then open a new terminal so the change is
visible:

```bat
setx DB_USERNAME root
setx DB_PASSWORD "your MySQL password"
```

| Variable | Default | Meaning |
|----------|---------|---------|
| `DB_USERNAME` | `root` | MySQL user |
| `DB_PASSWORD` | *(empty)* | MySQL password |

`START.bat`, `STATUS.bat` and `DATABASE.bat` all understand this form, so they keep
working whether the password is supplied through the environment or written
directly into the properties file. No script ever prints the password, and because
the value lives outside the project folder it cannot be committed by accident.

If you prefer to keep the password in a file, replace the two lines above with the
user name and the password directly - but do not commit that change.

## 4. `database.sql` (optional, destructive)

```bash
mysql -u root -p < database.sql
```

> **Warning - this script drops all five tables.**
> `database.sql` starts with `DROP TABLE IF EXISTS` for `users`, `food_items`,
> `orders`, `order_items` and `payments`, so running it against a database that
> already holds data **permanently deletes that data**. Only run it on a fresh
> database, for example:
>
> ```bash
> mysql -u root -p -e "CREATE DATABASE kiot_canteen_manual CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
> mysql -u root -p kiot_canteen_manual < database.sql
> ```

The script also seeds the 2 demo users with working BCrypt hashes, so the demo
logins in this README work after a manual import. You normally do not need it -
`START.bat` sets the database up by itself.

## 5. Running it

### Option A - `START.bat` (easiest, recommended)

Double-click `START.bat`. It runs five steps: check Java, check MySQL, check port
8080, build the jar if any source file is newer than the jar, then start the server
in its own window and open the browser. If the app is already running it says so
instead of starting a second copy.

### Option B - Maven directly

```bash
cd backend

# run straight from source (good for development)
mvn spring-boot:run

# or build the jar and run it
mvn -DskipTests package
java -jar target/kiot-canteen.jar
```

There is no Maven wrapper in this project, so `mvn` must be on your `PATH`.

### Option C - the runnable jar

```bash
cd backend
java -jar target/kiot-canteen.jar
```

### Startup output

```
Tomcat started on port 8080 (http) with context path '/'
Started CanteenApplication in ~7.5 seconds
[seed] inserted 17 food items        <- only on a first run against an empty menu
```

The seeder only prints when it actually changes something, so a restart against an
already-seeded database is silent. Demo passwords are **not** printed to the log.

### Helper scripts

| Script | What it does |
|--------|--------------|
| `START.bat` | Check prerequisites, rebuild if needed, start the server, open the browser |
| `STOP.bat` | Stops only the KIOT java process, then confirms port 8080 is free. MySQL and all other programs are left running |
| `STATUS.bat` | Prints Java / MySQL / database / port / application status and a final verdict |
| `OPEN_APP.bat` | Opens <http://localhost:8080> if the app is running, otherwise tells you to use `START.bat` |
| `DATABASE.bat` | Read-only MySQL browser: tables, row counts, per-table rows, a joined order overview, and `DESCRIBE` output. It only ever runs `SELECT` / `SHOW` / `DESCRIBE` and never prints password hashes |

## 7. Implemented features

**Authentication**
- Email + password login with BCrypt hashing
- Opaque session token held server-side in memory, sent as the `X-Auth-Token` header
- `401` when unauthenticated, `403` when asking for another student's order, `404`
  for an order that does not exist
- Logout invalidates the token immediately; the session survives a page refresh
  because the token is kept in `localStorage`

**Menu**
- 17 canteen dishes across 8 categories (All, Rice, Biryani, Noodles, Parotta,
  Dosa, Idli, Tiffin)
- Live search across dish name and description
- Category filter chips that combine with the search box
- Veg / non-veg badge, prep time, price and availability state on every card
- Full dish detail screen

**Cart**
- Add, increase, decrease and remove items
- Live total, plus an item-count badge in the header
- Cart persisted in `localStorage`, so a refresh does not lose it
- An empty cart cannot reach the pickup or payment steps

**Pickup**
- Date picker covering today through the next 7 days
- Five 15-minute slots
- Both a date and a slot are required before continuing (the button stays disabled)
- Past dates and dates beyond the window are also rejected by the server

**Payment (demo only)**
- UPI, Card and Cash at counter
- UPI and Card mark the order `PAID`; Cash marks it `PENDING`
- No banking details are collected anywhere in the app

**Orders**
- Order numbers formatted `KIOT-CAN-<year>-00001`, sequential per calendar year
- The total is always recalculated on the server from the database prices, so a
  tampered request cannot change what is charged
- Stored across the five tables `users`, `food_items`, `orders`, `order_items`,
  `payments`, with one `payments` row per order
- `POST /api/orders` answers **200 OK** with the full order payload

**QR code**
- A real, scannable QR code generated server-side by ZXing and served as a PNG
- Encodes order ID, student name, student ID, pickup date, pickup slot, order
  status, payment method, payment status, total and item count
- Shown on the confirmation screen and in a modal from My Orders
- Fetched with the auth header and rendered from a blob URL, because a plain
  `<img src>` cannot send the token

**My Orders**
- Only the signed-in student's orders, newest first
- Order code, placed time, items with quantities and line totals, total, pickup
  details, payment method and status, order status, and a "View QR" action
- Empty state when there are no orders

**UI / UX**
- Deep navy / white / light grey palette with a teal accent
- Responsive: a top navigation on desktop, a bottom tab bar on mobile
- Dish photos are hosted on Wikimedia Commons; if an image cannot load, the card
  falls back to a gradient tile with the dish name instead of a broken-image icon
- Toasts, loading skeletons, disabled states and `prefers-reduced-motion` support

## 8. API reference

| Method | Endpoint | Auth | Purpose |
|--------|----------|------|---------|
| POST | `/api/auth/login` | no | Log in; returns a token and the user |
| POST | `/api/auth/logout` | yes | Invalidate the current token |
| GET | `/api/auth/me` | yes | The signed-in user |
| GET | `/api/foods` | no | Menu; supports `?search=` and `?category=` |
| GET | `/api/foods/categories` | no | Category list, including `All` |
| GET | `/api/foods/pickup-config` | no | Allowed slots and the max advance-days window |
| GET | `/api/foods/{id}` | no | A single dish |
| POST | `/api/orders` | yes | Create an order (200 OK) |
| GET | `/api/orders/my` | yes | The signed-in student's orders |
| GET | `/api/orders/{id}` | yes | One order - owner only, otherwise 403 |
| GET | `/api/orders/{id}/qr` | yes | QR code as `image/png` - owner only |

Authenticated calls need the header `X-Auth-Token: <token>`. The menu endpoints
are deliberately public so the food list could be browsed without a session; every
order endpoint requires one.

### Error codes

| Status | When |
|--------|------|
| 400 | Validation failure - empty cart, missing date, invalid slot or payment method, unknown dish, quantity below 1, date in the past, date beyond the booking window |
| 401 | Missing or invalid session token |
| 403 | Reading an order that belongs to another student |
| 404 | Unknown order, dish or API path |

### Example

```bash
# log in
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"student@kiot.edu","password":"canteen123"}'

# create an order (foodItemId 14 is Idli at 20.00; use a date within 7 days)
curl -X POST http://localhost:8080/api/orders \
  -H "Content-Type: application/json" \
  -H "X-Auth-Token: <token>" \
  -d '{"items":[{"foodItemId":14,"quantity":2}],
       "pickupDate":"<today + 1 day, YYYY-MM-DD>",
       "pickupSlot":"12:30 - 12:45",
       "paymentMethod":"UPI"}'
```

`6` Egg Biryani, `7` Chicken Biryani, `8` Veg Noodles, `9` Chicken Noodles,

## 9. Database schema

```
users         id, name, email(uniq), password_hash, student_id, phone, role, created_at
food_items    id, name, description, price, category, image_url, available,
              prep_time_mins, is_veg, created_at
orders        id, order_code(uniq), user_id->users, total_amount, pickup_date,
              pickup_slot, payment_method, payment_status, order_status, created_at
order_items   id, order_id->orders, food_item_id->food_items, item_name,
              unit_price, quantity, line_total
payments      id, order_id->orders(uniq), method, status, amount, reference, created_at
```

`order_items.item_name` and `unit_price` are copied at order time, so historical
orders stay correct even if the menu or a price changes later.

## 10. How to verify it works

1. **Credentials** - confirm `echo %DB_PASSWORD%` prints your MySQL password. If it
   is empty, set it with `setx` and open a new terminal, otherwise the server
   starts but cannot reach the database.
2. **Startup** - run `START.bat`. You should see Java OK, MySQL OK, port free, a
   successful build, and then `Started CanteenApplication` in a new window.
3. **Health** - run `STATUS.bat`. Every line should report the item as available or
   running, and the verdict should be "everything looks good".
4. **Login** - sign in as `student@kiot.edu` / `canteen123`. A wrong password must
   show "Invalid email or password" and must not reveal the app.
5. **Menu** - the Menu tab shows 17 cards. Searching `dosa` narrows it to 2, the
   Biryani chip narrows it to 3, and a nonsense search shows the empty state.
6. **Images** - every dish photo should render. If you go offline they degrade to
   gradient tiles with the dish name, never to broken-image icons.
7. **Cart maths** - add Idli twice and Vada once: the total must read 65.00. Press
   the `-` on Idli: 45.00. Remove Vada: 40.00. Clear the cart and the empty state
   appears, and the Pickup step becomes unreachable.
8. **Pickup** - "Proceed to payment" stays disabled until both a date and a slot
   are chosen.
9. **Payment and ordering** - place the order with UPI, then again with Cash. The
   confirmation must show a `KIOT-CAN-<year>-00001`-style code, `CONFIRMED`, and
   `Payment: PAID` for UPI / Card but `Payment: PENDING` for Cash. The cart must be
   empty afterwards.
10. **QR** - the QR image must appear on the confirmation screen, and "View QR" in
    My Orders must reopen it. Scanning it returns the order code, student ID, pickup
    time, status and total.
11. **Isolation** - log out, sign in as `demo@kiot.edu`, and My Orders must not
    contain the other student's orders.
12. **Persistence** - restart the app. Your orders are still in My Orders, and the
    row counts in `DATABASE.bat` are unchanged.
13. **Data** - run `DATABASE.bat`, choose `7` for row counts. The users table holds
    2 rows, `food_items` holds 17, and `orders` and `payments` always have the same
    number of rows.

## 11. Known limitations

These are deliberate scope decisions, not defects, but they are worth knowing:

- **No automated tests.** There is no `src/test` folder; the project was verified
  by manual API, database and browser testing instead.
- **Sessions are in memory.** Restarting the server signs everyone out, and the
  project cannot be scaled to more than one instance as-is.
- **Payments are simulated.** UPI and Card are marked `PAID` the moment the order is
  created. No payment gateway is contacted and no money moves.
- **The order number counter is per-process and per-year.** It scans for the next
  free number, which is fine for a single instance but is not multi-instance safe.
- **The menu is static.** There is no staff screen, so dishes cannot be added,
  repriced or marked sold out at runtime, and there is no stock control.
- **Order status never advances.** Every order is created `CONFIRMED` and stays
  there; nothing moves it to `PREPARING`, `READY` or `COMPLETED`.
- **No registration.** Accounts are created only by the seeder, so a new student
  cannot sign themselves up.
- **Food photos come from Wikimedia Commons over the internet.** Offline, the cards
  show the designed gradient fallback rather than a photo.
- **CORS allows any origin** (`allowedOriginPatterns("*")`), which is convenient
  locally but should be restricted before any real deployment.
- **Database credentials come from environment variables.** `DB_USERNAME` and
  `DB_PASSWORD` must be set on each machine that runs the app. That keeps the
  password out of the project, but it is one extra setup step, and a plain
  environment variable is a convenience rather than a real secret store.

## 13. Troubleshooting

**`START.bat` says the build failed**
Run it again in a terminal so Maven's output is visible:
`cd backend && mvn -DskipTests package`. This is nearly always a missing Maven
installation or a wrong MySQL password, not a code problem.

**`Access denied for user 'root'@'localhost'`**
The `DB_PASSWORD` environment variable is missing or wrong. Check it with
`echo %DB_PASSWORD%`, then run `setx DB_PASSWORD "your MySQL password"` and open a
new terminal so the value is visible.

**Port 8080 is already in use**
```bash
netstat -ano | findstr :8080
taskkill /PID <pid> /F
```
Or change `server.port` in `application.properties`. `STOP.bat` also clears this
automatically if the process is the one it started.

**The menu is empty or tables are missing**
The seeder only adds rows that are missing, so an empty menu means the database
exists but is not the one the app is using. Check the JDBC URL, or force a clean
reseed:
```sql
DROP DATABASE kiot_canteen;
```
then run `START.bat` again.

**The QR image is blank**
The QR endpoint needs the `X-Auth-Token` header, so it cannot be opened directly in
a new browser tab. The frontend fetches it with the header and renders it from a
blob URL. Use the **View QR** button inside My Orders.

**Dish photos show gradient tiles**
Those tiles are the intended fallback. Photos are loaded from Wikimedia Commons and
need an internet connection; each card falls back to a gradient tile with the dish
name rather than showing a broken image.

**`DATABASE.bat` does nothing when I type**
It is a menu that reads one number at a time. Press `0` and Enter to leave.
